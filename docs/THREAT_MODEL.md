# TrustVault Threat Model

The following matrix documents the threat model for the TrustVault platform. Each entry details the attack vector (with associated CWE classification), the architectural and programmatic defence implemented, and the automated test that proves the defence is operational.

| Attack & Threat Vector | Defence | Test That Proves It |
|---|---|---|
| **Credential Stuffing & Rapid Password Brute-Force**<br>`CWE-307: Improper Restriction of Excessive Authentication Attempts`<br>Adversary launches automated bot scripts attempting hundreds of credential combinations per minute against `/auth/login`. | Scoped `express-rate-limit` middleware (`loginRateLimiter`) applied to `/auth/login` and `/api/auth/login`. Enforces a strict ceiling of 5 requests per minute per IP, rejecting the 6th attempt with HTTP `429 Too Many Requests`. | [`tests/security-controls.test.js`](file:///c:/Users/jithe/coding/TrustValut/tests/security-controls.test.js)<br>`Express Rate Limiter on /auth/login (5 attempts per minute)`<br>→ `should allow 5 consecutive login attempts and block the 6th with 429 Too Many Requests` |
| **Cross-Site Request Forgery (CSRF)**<br>`CWE-352: Cross-Site Request Forgery`<br>Adversary tricks an authenticated victim into visiting a malicious site that executes cross-origin state-changing requests (e.g. file upload, edit, delete, grant) with the victim's session cookies automatically attached. | Double-Submit Cookie CSRF protection via `csrf-csrf` using cryptographically signed 32-byte tokens in the `trustvault.x-csrf-token` cookie, verified against the custom `x-csrf-token` HTTP header and bound to user session. Rejects forged requests with HTTP `403 Forbidden`. | [`tests/security-controls.test.js`](file:///c:/Users/jithe/coding/TrustValut/tests/security-controls.test.js)<br>`csrf-csrf Double Submit Protection`<br>→ `should reject state-changing request with 403 when CSRF is enforced and token is missing`<br>→ `should accept state-changing request when valid CSRF token and cookie are provided` |

| **Cross-User Insecure Direct Object Reference (IDOR) - Tamper via PUT**<br>`CWE-639: Authorization Bypass Through User-Controlled Key`<br>User B sends `PUT /documents/:id` to overwrite User A's document metadata. | `updateDocumentMetadata()` invokes `authorize(user, doc, 'edit')`.
